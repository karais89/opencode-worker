# Grok Build 직접 실행과 두 스킬 Worker 벤치마크 (2026-09-26)

## 목적과 조건

Windows 네이티브 환경에서 동일한 작은 Git 저장소 작업을 Grok CLI 직접 실행과 **설치된** `$grok-worker`로 각각 수행했다. 저장소에는 실패하는 `normalize_tags` 구현과 두 테스트가 있었다. 작업 지시는 공백 제거, 소문자 변환, 빈 값 제외, 입력 순서대로 중복 제거, `tags.py`만 변경, `python -m unittest -v` 통과였다. 두 경로에 동일한 Worker 프롬프트 생성 함수를 사용했으며, 저장소 절대 경로만 달랐다. CLI 모델은 기본값인 `grok-4.7`이었다. Grok CLI 버전은 `1.0.41`; 설치 번들은 `2.1.0`이었다.

실행 시간은 각 프로세스 시작부터 종료까지의 경과 시간이다. 토큰과 비용은 CLI 종료 이벤트 또는 Worker 요약에 실제 표시된 값만 기록한다. 각 실행 후 별도 Python 테스트와 수용 조건 네 가지를 확인했다. 모델 품질과 속도의 통계적 차이를 주장할 만큼 반복하지 않았다.
