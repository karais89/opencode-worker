# Worker 공통 계약

OpenCode와 Grok Build 모두 Head가 목표와 완료 조건을 정하고 Worker **한 세션**에 맡긴다. 확인된 실제 저장소의 절대 경로를 사용하고 기존 사용자 변경을 보존한다. 빈 폴더나 지시 파일만 있는 임시 폴더를 작업 대상으로 삼지 않는다.

지시는 자기완결적인 UTF-8 파일로 저장하고 **8 KiB 이하**로 유지한다.

```text
GOAL: 달성할 목표
PLAN: 이미 결정된 핵심 방향
CONSTRAINTS: 작업 범위와 지켜야 할 제약
DONE WHEN: 확인 가능한 완료 조건
```

실패·거부·비정상 종료·검증 실패는 숨기지 않는다. 부분 변경을 보존하고 자동 재실행하거나 다른 엔진으로 전환하지 않는다. 결과의 **최상위 `status`를 우선**하며 `needs_escalation`을 완료로 보고하지 않는다. `validation_evidence.status=observed_pass`는 선언한 로컬 명령의 exit 0을 관측했다는 뜻이며 구현 품질이나 요구사항 충족을 증명하지 않는다.

Head는 요구사항과 `result.changed`, `validation`, `risk`를 대조한다. 구체적인 불일치나 고위험 변경이 있을 때 필요한 부분을 추가 확인한다. 사용자에게 **변경한 것 / 실제 검증한 것 / 남은 위험**을 짧게 보고한다. 측정하지 않은 비용·토큰 절감률은 추측하지 않는다.
