# OpenCode Worker

Head decides the goal, important requirements, constraints and completion criteria. Write one short self-contained brief, referencing REQUEST.md if present. Writer discovers AGENTS and original Skills/tools, explores, implements, tests, debugs and fixes failures in its own session. Do not explore implementation first.
Split large requests into cohesive units that can each be implemented and validated; delegate already-small requests as they are and avoid unnecessary fragmentation.

Run `python3 <this-skill>/scripts/worker.py --project /absolute/repo run --brief /absolute/brief.txt --evidence-dir /outside/repo/evidence`. For an explicit $opencode-worker request, add --explicit (this does not override off mode or host authorization). Saved model routing remains. One canonical project-directory lock prevents overlapping workers in the same checkout; independent checkouts may run concurrently. Honor host authorization; never bypass a rejection or replay possible side effects. No reviewer, contract gate or automatic corrective chain on this path. Normal tasks use exactly one Writer. Do not manage individual writer tool calls.

In a restricted Codex host, request the normal host permission escalation on the FIRST OpenCode model lookup or Worker launch (for example, exec_command with sandbox_permissions="require_escalated"). OpenCode needs its user log/cache/config directories, the project lock and provider network access; repository write access alone is insufficient even for `models`. Use the host's normal permission interface with the authorized task/provider scope; do not make a predictably blocked sandbox attempt first. If the host rejects the request or requires missing user authorization, stop and report it. This instruction does not grant permission, bypass review, change Worker permissions, or authorize retry/recovery. Do not add per-tool approval relays inside the Worker.

For a completed result, check request/result agreement, successful validation, obvious scope violation and unresolved risk. If clear, finish. No routine source/diff reread, private evidence read or test rerun. Investigate only a concrete suspicion. The Writer submits through codex_worker_submit_result; invalid fields return an error to the same live Writer for report-only correction. Final prose/Markdown is ignored by the completion protocol. Missing/rejected/conflicting submission or an execution failure is needs_escalation, not a reason to replay the Worker. The tool uses the existing OpenCode plugin SDK and is loaded only for this process; no project/global configuration is written.

Only when Head has reproduced a concrete implementation defect with actual input, or identified an unambiguous requirement violation, allow ONE corrective Writer for the same task. Vague suspicion, uncertainty, a desire for more review, or report/transport failure does not qualify. Write a short correction brief containing only the observed problem (input/evidence) and expected behavior; preserve the original task scope. Run the same command and model/options with `--fix-from <original-evidence_dir>/writer.json --brief <correction.txt>`. Use the evidence_dir returned in the original compact result; no routine private-evidence read is needed. Writer owns the targeted fix and necessary tests. Then perform only a focused result check; finish if resolved. If unresolved or a second correction is needed, stop with needs_escalation and the remaining concrete issue; do not launch another Worker or take over implementation. Do not evade the limit with a fresh ordinary run. The controller records one correction attempt against the original evidence under the existing project lock, including failed/interrupted attempts, and rejects correction-of-correction. This is an explicit exception, never a default step.

All existing normal repository-local capabilities remain: files, shell, dependencies, CLI/MCP, Editor, tests/build/debug/fix. Original shared Skills stay read-only. Secrets, global/system config, unapproved external changes, destructive git, push/publish/deploy, broad deletion and nested workers remain restricted. Read references/control.md only for setup, routing or a specific execution problem.

Keep handoffs visible with brief conversational updates only when the stage changes: delegation requested (what was delegated), execution confirmed if available, result received (Worker-reported validation; Head check pending), and final Head outcome. Announce a corrective handoff only when it actually occurs, with the concrete issue and `correction 1/1`. Distinguish a launch request from confirmed execution and a Worker completion report from Head acceptance; never infer an unobserved status. Use evidence already available from the normal workflow, with no extra model calls, polling or log reads solely for display. Do not narrate individual tool calls or repeat unchanged status.

Final reply: outcome, validation, remaining risk, then one short line using observed model, total executed Writer calls and summed elapsed seconds: `Worker: <model> · 1회 · <seconds>초` or `Worker: <model> · 2회(수정 1회) · <seconds>초`. Use actual evidence, not the example model or invented timing; state unavailable fields honestly. If no Worker launched, say `Worker: 미사용 · <short reason>`. Do not claim tokens saved without measurement. This is a thin shortcut for manual Head → OpenCode → Head, not a new orchestration system.
